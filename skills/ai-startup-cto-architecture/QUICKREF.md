# AI 创业 CTO 技术架构 - 快速参考

## 🏗️ 4 阶段技术架构

| 阶段 | 用户 | 关键选择 |
|------|------|---------|
| -1 MVP | 0-100 | 单体 + 托管 + 1-2 人 |
| 0 验证 | 100-1k | 容器化 + 主从 + 测试 |
| 1 规模 | 1k-10k | 微服务 + 容器编排 + 监控 |
| 2 平台 | 10k+ | 中台 + 数据湖 + 安全 |

## 📊 技术债 4 维评估

每项 0-10：代码质量 / 文档 / 架构 / 运维

- 0-3 优 / 4-6 中 / 7-10 差
- 偿还优先级：P0 安全 → P1 架构 → P2 运维 → P3 代码 → P4 文档

## 🔧 选型 5 原则

1. 团队熟悉度 > 技术先进性
2. 托管服务 > 自建
3. 主流框架 > 小众
4. 可演进 > 一步到位
5. 可观测 > 不可观测

## 📈 DORA 4 指标

| 指标 | 优秀 | 差 |
|------|------|-----|
| 部署频率 | 每日多次 | 季度+ |
| 变更前置时间 | < 1h | > 1月 |
| 变更失败率 | 0-15% | > 45% |
| 故障恢复时间 | < 1h | > 1周 |

## 👥 团队规模演进

-1: 1-2 人 / 0: 3-5 人 / 1: 8-15 人 / 2: 20+ 人

## 🛠️ 路线图 4 维度

业务（季度）+ 架构（半年）+ 技术债（季度 30%）+ 创新（月 10%）

## 🔒 安全 5 原则

最小权限 / 零信任 / 纵深防御 / 数据加密 / 审计日志

## 💰 FinOps 降本 5 招

预留实例 / Spot / 自动伸缩 / 缓存 / 数据归档

## 💡 CTO 5 反常识

1. 不写代码才是真本事
2. 招贵的人比便宜的人便宜
3. 删代码比写代码难
4. 重写 = 万恶之源
5. 技术债不可怕，假装没有才可怕

## 💡 1 句话

> CTO = 架构 + 团队 + 决策。
> 技术债是复利，安全债是高利贷。
